> **固定档名，改设计覆盖它。**
> 写于 2026-08-20 深夜 · J 决定：「我希望是很好用，而不是被锁死不好用的系统。
> 不然为什么人们要用这个系统？很现实的问题。」
>

## 0. 一句话

**防幻觉的正解是「让 AI 看得到真的资料并且指出处」，不是「不给它看」。**

现在的助手做的是后者。它被 prompt 第 1 条绑住眼睛：

```
NEVER invent a fact about this organisation's own records.
You cannot see their minutes, donations, receipts or constitution in this conversation.
```

所以理事问「今年花了多少 AI 钱」，它回「我看不到，请去某一页」。
**那不是安全，那是没用。** 而没用的东西没有人会付钱。

## 2. 形状：一个有工具的助手

```
使用者讲一句话
   ↓
模型决定要不要用工具（可以用好几个、可以来回几轮）
   ↓
工具 = 一支 RLS-scoped 查询 ＋ TypeScript 算好的总数
   ↓
模型只用工具回来的东西回答，每个事实带出处
   ↓
画面：答案 ＋ 可点的出处 ＋（需要的话）一颗「去那一页」
```

### 工具清单

> 🔴 **更正（2026-08-20 深夜）**：这一份稍早把 `guna_ai(period)`（问 AI「今年花了多少 AI 钱」）
> 列成**第一支工具**。**J 推翻了**：「用户没办法问 AI 这个月用了多少 AI，还是多少 TOKEN 什么的。」
> **那一支拿掉了**，理由在 `docs/模型评测与总控台.md` 第 7 节 ——
> 简单说：**他们的记录该给 AI 看，我们的成本不该。** 那是两件事。
> 使用者要看用量，去「设定 → AI 用量」看**百分比**；J 要看金额，去 `/admin`。

| 工具 | 做什么 | 资料从哪来 | 备注 |
|---|---|---|---|
| `cari_minit(query, from?, to?)` | **「我记得有一次开会说了什么」** | `minutes_docs.final_md` | 🔴 需要 pgvector，见第 3 节。**这是第一支要做的** |
| `cari_derma(...)` / `cari_resit(...)` | 捐款、收据 | 沿用 `api/ask` 现有的 `searchRecords()`，捐款人名维持 masked | 总数一律 TS 算 |
| `perlembagaan(q)` | 章程条文 | `constitutions` | 要引出条文原文 |
| `senarai_ahli()` | 理事名单、谁缺 `name_official` | `committee_roster` | |
| `tarikh_penting()` | 死线（年报、AGM） | `deadlines` | 讲死线一律附「去哪里核对」 |
| `pergi(page)` | 导航 | `ASK_ROUTES`（现有的） | 不用 AI，但变成工具让模型自己选 |

### 接地规矩（这几条取代「不给看」）

1. **只能讲工具回来的东西。** 没有工具回来的，就说「我查不到」，不要推测。
2. **每个事实要带出处** —— 哪一场会议、哪一天、哪一条。画面上是可点的连结。
   使用者点得进去看原文，AI 就骗不了人。
3. **数字一律照抄。** 总数由 TS 算好、格式化好塞进 prompt，模型不准重算、不准四舍五入。
4. **工具全部走 user-scoped client。** RLS 是边界，不是 prompt 里的一句话。

## 3. 搜寻：为什么一定要 pgvector，而且一定要现在

J 要的是「**我记得有一次开会说了什么，你帮我找出来**」。

| 做法 | 「谁负责青少年班的活动」找不找得到记录里的「小小班策划由余老师带」 |
|---|---|
| 现在的 `ILIKE %词%` | ❌ 要一模一样的字才行 |
| Postgres 内建全文检索 | ❌ 中文不会切词，等于还是抠字 |
| **pgvector ＋ embedding** | ✅ 这就是这题的正解 |

**🟢 而且现在是最便宜的一刻。** J 正要建**新 Supabase** ——
`create extension vector` ＋ embedding 栏位 ＋ 索引，跟其他 migration 一起跑一次就好。
**新库建完才想起来，就变成要在活的资料库上贴 migration。**（跟 `refunded_at` 完全同一个道理。）

### 要写的 migration（写，不要执行）

```
supabase/migrations/20260822000000_minutes_search.sql
  create extension if not exists vector;
  alter table minutes_docs add column if not exists embedding vector(768);
  alter table minutes_docs add column if not exists embedded_at timestamptz;
  create index ... using hnsw (embedding vector_cosine_ops);
  -- RLS：沿用同一个 org_id in (select accessible_orgs()) 的模式
```

### 🔴 维度：一个会咬人的点（2026-08-20 用 J 自己的 key 实测）

> ⚠️ **更正**：这一份稍早推荐 `text-embedding-004`（768 维）。
> **那支模型在 J 的 key 上根本不存在。** 实际问过 API，能用的 embedding 只有三支：
> `gemini-embedding-001` · `gemini-embedding-2-preview` · `gemini-embedding-2`。

| 实测 | 结果 |
|---|---|
| 三支的**预设维度** | **3072** |
| 🔴 pgvector 的 hnsw 索引上限 | **2000 维** → **3072 建不了索引** |
| `gemini-embedding-001` 要 768 | ✅ 拿到 768 |
| `gemini-embedding-001` 要 1536 | ✅ 拿到 1536 |
| `openai:text-embedding-3-small` | 1536（备案） |

**选 `gemini-embedding-001` ＋ `outputDimensionality: 768`**：安全地低于索引上限、
索引快、储存小、品质损失很小，而且留在 Gemini 这边（`EXTRACT` / `LONG_DOC` 已经在那），
少一个厂商依赖。

⚠️ **维度写进 migration 的 `vector(768)` 就固定了。**
之后要改 = 重建索引 ＋ 重算全部 embedding。现在就想清楚。

### 什么时候算 embedding

**在 `status` 变成 `confirmed` 的那一刻**（记录被人确认了才算数），
外加一支补算既有资料的脚本。算 embedding 要不要计入 AI 额度：**建议不计**
—— 它不是使用者要的动作，而且很便宜。写进 `方案与权益设计.md` 第 4 节的「永远免费」。

## 4. 免费／付费：J 的线，比原本的墙好

**J 2026-08-20：「免费版如果封存的 AI 就读不到，他需要付费才能。」**

做法：**每一支工具的 SQL 都套上跟 `history.visible_months` 同一个 `WHERE`。**

关键是找到了但被封存的时候，**不能装作不存在**：

> 「我找到 **2 场**会议提到青少年班活动 —— 5 月 12 日和 6 月 8 日。
> **更早还有 3 场**也提到，在 __ 方案里看得到。」

🔴 **一定要讲出「还有 3 场」这个数字。** 这比撞墙好，因为它**正好在证明了价值的那一刻**要钱 ——
使用者刚刚亲眼看到助手真的找得到东西。

⚠️ 仍然是**查询上的过滤，不是删除**（`方案与权益设计.md` 原则②）。
会议记录是法定纪录，看不到 ≠ 不存在，付费当下全部回来。

## 4.5 扣额度：打了厂商就算用掉

**J 2026-08-20：「他给什么我们让 AI 弄出来，弄不出来还是有错也是没办法…
有些是自己照片糊还是什么，也不可能我们帮他付费吧。」**

对。这一行所有人都写着「AI 会出错，请自己核对」，我们没有理由更慷慨。
而且「是我们的错还是照片的问题」这个分辨本身也会分辨错，还要人力判 —— 徒增一层会坏的东西。

### 规则（一句话）

> 🔴 **打了厂商 ＝ 用掉一次。没打到厂商 ＝ 不扣。**

| 情况 | 打了厂商吗 | 扣不扣 |
|---|---|---|
| 照片糊、两次都解析失败、读出来是垃圾 | ✅ 我们付了钱 | **扣**。画面上讲清楚「这次读不出来，用掉了 1 次」＋ **教他下次怎么拍**（不是道歉，是帮他成功） |
| 模型判定超出范围（`in_scope: false`） | ✅ **模型跑完才知道的** | **扣** |
| 厂商连不上、网路断、呼叫前就 throw | ❌ 没产生费用 | **不扣**（退）。这不是补偿，是我们根本没做那件事 |
| 没有符合的记录、导航走写死字串 | ❌ 根本没打 | **不扣** —— 而且最好是**一开始就别扣** |

### 🔴 现在有个真的洞，不是理论

`src/app/api/chat/route.ts:202`：呼叫模型 → 模型回 `in_scope: false` → **退额度**。
也就是 **AI 已经跑完、钱已经付了，使用者不用付任何代价**。

> 有人可以一直跟它闲聊不相干的东西，**每一轮都免费**，而每一轮我们都在付钱。

`api/ask/route.ts:128` 的 `out_of_scope` 退款是同一个形状（classify 已经打出去了）。
**两个都要拿掉。**

### 实作

- 扣仍然**在打厂商之前**（防并发绕过额度：一次丢 100 个请求全部通过检查）
- `refundUsage()` 只在**厂商没被打到**时呼叫。现在 14 个呼叫点，改完应该剩下少数几个
- **`refunded_at` 栏位照做**（C2-2 那支 migration），但**理由变了**：
  它不再是客服工具，是**厂商健康度指标** —— 「打不到厂商」的比率一高，
  就是去看厂商或网路，不是去看客服
- **退款率进管理台**（`方案与权益设计.md` 第 5.1 节）
- Rule 10 里「拒答一律退额度」那句改成「**没打到厂商才不扣**」
