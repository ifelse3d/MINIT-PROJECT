**两个坑的实际解法**（跟下面写的建议不一样，写在这里免得下次又踩）：

1. 坑 1 **不能只抽 hook**。`usePersistentState` 每个实例各有一份 React state，

   和 `src/app/minutes/minutes-store.tsx` 各自只存在一份，四／三页用
   `useRegister()`／`useMinutes()` 拿。Next 的 layout 在同一段路由之间不会卸载，
   所以「拍到一半的账页」换页也还在。
2. 坑 2 照做了：`downloadFromApi`→`src/lib/download-file.ts`、
   `todayIsoMalaysia`→`src/lib/history.ts`、`isRegisterDonationArray`→
   `src/lib/receipts.ts`，三支都补了测试（488 → 496）。
   `DonationEditor`、custody 标签、`FieldRow`、minutes 的 localStorage 层
   也各自独立成档。

顺手做掉的：`SectionTabs`（跨页版的进度条，是连结不是按钮，上一页下一页都能用）·
`PageSection`／`NextStepLink`（StepCard 变成一页之后剩下的东西）·
左边选单「会议记录」「财务」变成可展开的 group ·

### 拆之前要知道的两件事（会踩到）

1. **状态是 localStorage，不是 props。** `money-review.tsx` 用
   `usePersistentState`（`minit:money:*`）存名册、批次。所以**换页不会掉资料** ——
   这也是拆页可行的原因。但要先把那一堆 `useState` 抽成一个共用 hook
   （建议 `src/app/money/use-register.ts`），否则四页各自 `usePersistentState`
   同一个 key，同一个分页里两个组件互相看不到对方的更新。

### 4.1 「写进资料库」那一条，三张表的答案不一样

三张表**从第一支 migration 就存在**，Phase 7 的 RLS 也早就配好了 ——
`src/db/activity.ts` 里却一个 `insert` 都没有。读得到，写不进去。

| 表 | 做法 | 为什么 |
|---|---|---|
| `events_meetings` | 真的写进去，本机 localStorage 仍是工作副本，`mergeEvents` 做联集 | 两边都可能有对方没见过的活动。任一边整份覆盖另一边，就是删掉别人的会 —— 而删掉的活动＝没有人出席的会议 |
| `remittance_batches` | 真的写进去，交接时写、总会确认时**改写同一列**（`client_id` upsert） | 三个里面最要紧的。交接是「甲说他把钱给了乙」，值多少取决于**两边都看得到的那份纪录**。分会出纳手机掉了，等于所有交接的证据跟着掉 |
| `deadlines` | **只存「打勾」，不存死线本身** | 死线是**算出来的**（年报＝AGM 日期＋60 天，e-Invois＝法定月底），两个输入都已经在资料库里，每一台机器都会算出同一份。把算出来的东西再存一份，就是第二份可能跟第一份不一致的资料 —— 比不存更糟。真正缺的是另一半：`status = 'done'` 从第一支 migration 就存在，**全 app 没有一个地方写过它**，所以六月已经报完年报的出纳，接下来半年一直被红字追着喊 |

### 4.2 🔴 一条以后都要照做的规矩

**这些程式码必须在「migration 还没跑」的资料库上照常运作。**

J 是自己手动跑 migration 的（D8），所以永远有一段时间程式比资料库新 ——
而 PostgREST 只要被问到一个不存在的栏位，**整个 query 都会失败**。
所以 `src/app/calendar/actions.ts`、`custody-actions.ts`、`deadline-actions.ts`
每一支都：回传结果物件、绝不 throw、把「存不进去」当成正常结局由 UI 说出来。

这不是暂时的鹰架。**一个站在礼堂里只有一格讯号的秘书，处境跟一个还没跑
migration 的资料库一模一样**，两个都该有一个还能用的行事历。

而且失败一定要**说出来**：一个以为行事历是共用的委员会，比一个知道它不是共用的
委员会更糟。
