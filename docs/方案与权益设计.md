## 0. 三个原则（先写下来，之后有人想改要先推翻它）

**① 免费不能慷慨，但也不能让人读不准。**
免费层的成本几乎就是全部成本（每 org 每月 RM19.56，绝大部分是 AI）。所以免费一定要有墙。
**但墙不能砌在「读得准不准」上** —— 读得准是唯一会让人愿意付钱的那一刻，砍掉它等于砍掉转换。

**② 免费到期的东西「藏起来」，不是「删掉」。**
会议记录是法定纪录。一个社团三个月后回来发现去年的记录被系统删了，那不是客诉，那可能是真的害到人。
**看不到 ≠ 不存在。付费当下全部回来。** 逼单效果一样，风险差一个级距。
（唯一可以真的删的是**原始照片**，而且要在画面上讲清楚哪一天会删、删之前提醒。）

**③ 任何让纪录变得「比较不真实」的东西，永远不收费。**
审计行、`name_official` 缺了的警告、「这场会议不进年报」那句话、覆盖率检查 —— 这些不是功能，是正确性。
**把正确性放进付费墙 = 卖「不出错的权利」。** 那是这个产品最不该碰的一条线，也是评审最容易问的一题。
第 4 节有完整的「永远不收费」清单。

## 1. 资料形状

方案与额度是**资料**，不是程式码。改额度 = 改一行资料，不用部署。

```sql
-- 方案本身
create table plans (
  code        text primary key,          -- 'free' | 'basic' | 'standard' | 'branch'
  name_bm     text not null,
  name_zh     text not null,
  name_en     text not null,
  sort_order  int  not null,
  price_myr_monthly  integer,            -- 分为单位；null = 还没定价
  price_myr_yearly   integer,
  is_public   boolean not null default true,   -- false = 内部／试点专用
  created_at  timestamptz not null default now()
);

-- 一个方案给什么
create table plan_entitlements (
  plan_code   text not null references plans(code) on delete cascade,
  key         text not null,             -- 见第 2 节的词汇表
  value       jsonb not null,            -- 数字、布林、字串，一栏收完
  primary key (plan_code, key)
);

-- 一个机构在哪个方案
alter table orgs add column plan_code text not null default 'free'
  references plans(code);
alter table orgs add column plan_since   timestamptz;
alter table orgs add column plan_note    text;   -- 「试点，免费到 2026-12」
```

**读取的地方只有一个**：`src/lib/entitlements.ts` —— `entitlement(orgId, key)`，带快取。
🔴 **不要让任何画面直接读 `plan_entitlements`。** 一个额度在两个地方各判断一次，就会有一个地方判断错，而那正是 8/20 那个 bug 的形状（画面允许的比后端允许的多）。

⚠️ **`monthly_free_quota` 与 `extra_credits` 保留，不要删。** 它们现在真的在跑，而且被 `minit_admin.grant_ai_credits()` 用着。做法是让 `ai.monthly_actions` **覆盖** `monthly_free_quota`，加购仍然走 `extra_credits`。两套并存一段时间，确认新的对了再拆旧的。

## 3. 撞到墙的时候画面要说什么

**这一节跟额度数字一样重要，别跳过。** 一个挡下来却不说怎么办的墙，跟当机没有分别 ——
8/20 那次「是 Minit 这边出了问题」就是这个形状。

**规矩：挡下来的那一刻，同一个画面上要有三件事** —— 哪一格／为什么／怎么办。

| 撞到什么 | 画面上要出现 |
|---|---|
| 用量用完 | 「这个月的 AI 用量用完了。下个月 1 号会重来。**现在就要用**的话：加购，或换 __ 方案。」<br>🔴 **讲百分比，不要讲份数、不要讲 RM、不要讲 token。** 平常显示「本月 AI 用量 ▓▓▓▓▓░░░░░ 58%」。<br>⚠️ **2026-08-20 J 推翻了原本的「讲份数」** —— 一份便条纸和一本 30 页章程差几十倍成本，次数根本不是成本的代理。理由见 `模型评测与总控台.md` 第 6 节 |
| `doc.max_pages` 超过 | 「这份文件 **38 页**，__ 方案一次读 __ 页。可以分两次拍，或换 __ 方案一次读完。」<br>**先讲免费的那条出路，再讲付费的。** |
| `seats.max` 满了 | 「__ 方案可以有 __ 个人。要让财政也进来，换 __ 方案。」 |
| `history.visible_months` 之外 | 「__ 年之前的记录**还在**，__ 方案看得到。」<br>🔴 **一定要写「还在」。** 不写，人会以为被删了 |

## 5. 管理台（J 的最高权限）

### 5.1 第一版：唯读，看得见

**看数量和形状，不看内容。**

| 区块 | 显示什么 | 资料从哪来 |
|---|---|---|
| **机构清单** | 名字 · 方案 · 席位 用/上限 · 本月 AI 份数 用/上限 · **本月真实成本**（RM） · **毛利**（方案价 − 成本） | `orgs` ＋ `ai_usage.cost_micros` ✅ 已经在收 |
| **用量走势** | 每个 org 每月份数与成本，近 6 个月 | `ai_usage` |
| **模型分流** | 现在四个任务各自打到哪个厂商哪个模型（＝ `npm run check:ai` 的画面版） | `AI_MODEL_*` |
| **方案编辑器** | 改 `plan_entitlements` 的值，**不用部署** | `plan_entitlements` |
| **回报的问题** | 使用者按「回报问题」送来的（见 5.3） | `support_reports`（新表） |

> 🟢 **这一版把毛利从「算出来的」变成「量出来的」。**
> 现在对外讲的 73.4% 是 `unit-economics.ts` 模型算的；这一页显示的是**真的花了多少**。
> 那是两件事，而且后者才是评审会追问的那一件。

### 5.2 第二版：停权

🔴 **停权要做成资料库的一个状态，不是一段程式码。**

```sql
alter table orgs           add column status text not null default 'active'
  check (status in ('active','suspended','closed'));
alter table members_roles  add column status text not null default 'active'
  check (status in ('active','suspended'));
```

然后**让 `accessible_orgs()` / `accessible_orgs_writable()` / `accessible_orgs_admin()` 读它**。

**为什么一定要在那三支函式里，而不是在画面或 route 里：**
16 张表 × 4 条 policy 全部走那三支。挡在那里 =
**没有任何一条 route、任何一个未来才写的 API、任何一次手滑绕得过去**。
挡在画面上 = 只挡得住会看画面的人。

停权因此是**一行 UPDATE，立即生效，不用部署**；恢复也是一行，不会变成单向门。

**每一次停权都要写一行审计**（`platform_actions`：谁、什么时候、对谁、为什么、多久）。**那张表只能新增，不能改不能删。**

### 5.3 「我要知道有什么问题」—— 现在缺一块

⚠️ **实查：全 `src/` 只有 1 个 `console.*`（在 `layout.tsx`）。**
PDPA 上这是好事（内容从来不进日志），但代价是**现在没有任何地方看得到错误**。

最便宜有用的补法是一个使用者按的按钮，不是一套日志系统：

```sql
create table support_reports (
  id bigserial primary key,
  org_id bigint not null references orgs(id),
  user_id uuid,
  page text not null,            -- '/minutes' 第 2 步
  message text not null,         -- 使用者自己写的
  app_version text,
  created_at timestamptz not null default now(),
  status text not null default 'open'
);
```

画面上一颗「**回报问题**」，写清楚：**「我们看得到您写的这段话和您在哪一页，看不到您的文件内容。」**
这一条同时回答 J「不然也不知道有什么问题，或者反应的 bug 那些」。

### 5.4 关于「看别人的资料」

**不是「看别人资料一定犯法」，而是：你是资料控制者，只有在特定目的下才有合法基础去看**
（对方求助且同意 · 安全事故调查 · 法律义务）。

所以形状是：

- **平常完全看不到内容**
- 真的需要时走**破窗**：填理由 → 写 `platform_actions` 审计行 → **有时限** → 事后通知该 org

**看不到的东西，就不必为它负责。这是保护，不是限制。**

### 5.5 一个已经埋好的陷阱

🔴 **`service_role` 被刻意挡在 `minit_admin.*` 外面**（PART 2 的设计）。
所以管理台**不能**直接呼叫 `grant_ai_credits()`。加额度必须另外设计一条有审计的路 ——
**做到一半才发现这件事的成本很高，现在就写进设计。**

## 6. 数字怎么定 —— 这是实验，不是拍脑袋

J：「我们也要重新评估 AI 用量。这个我们也得做实验。」对。方法：

### 前置（要先做，不然量到的是空气）

1. **`ai_usage` 加 `user_id` / `member_id`**（J 8/19 点名的第 ⑥ 件，一小时 ＋ 一支小 migration）
   —— 不然只知道「这个 org 用了 40 次」，不知道是一个人用 40 次还是四个人各 10 次，而**席位定价要靠后者**。
2. **真的有人在用。** 现在 `ai_usage` 只有 14 笔，全是 J 自己的。

### 量什么

| 指标 | 拿来定什么 |
|---|---|
| 每 org 每月**用量**的 **p50 / p90**（照 `cost_micros` 算，不是照次数） | `ai.monthly_budget_micros`：**免费设在 p50 以下**（多数人会撞到墙 = 会看到付费理由），付费设在 p90 以上（付了钱的人不该再撞墙） |
| 每 org 每月**真实成本**（`cost_micros` 加总） | 每个方案的成本地板 → 价格必须高于它 |
| 每次操作的**平均页数** | `doc.max_pages` |
| 一个 org 有几个人**真的登入过** | `seats.max` |
| 从注册到第一份确认文件的**天数** | 免费层要不要更宽松（转换率问题） |

### 时程

- **两周真实资料**是最低限度（`STATE.md` 的 D1-L2 一直在等的就是这个，8/18 才开始收）
- 在那之前：**骨架照做，数字空着，画面上先不显示任何具体数字**
- 🔴 **价格一动，`unit-economics.ts`、deck、one-pager 全部要重算 —— 一律跑 `npm run economics`，不要手抄数字进任何文件**
