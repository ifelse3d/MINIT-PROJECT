## 🔴 1. 主要按钮：白字在紫色渐层上，全线不合格

`src/components/ui/button.tsx:13` 和 `glass.tsx:136`、`sidebar.tsx:50/193`：

```
bg-gradient-to-r from-[#7c6cf5] to-[#b3a6f7] text-white
```

| 渐层位置 | 白字对比度 | AA 正文 4.5 | AA 大字 3.0 |
|---|---|---|---|
| 起点 `#7c6cf5` | **3.95:1** | ✗ | ✓ |
| 中点 `#9a8bf6` | **2.84:1** | ✗ | ✗ |
| 终点 `#b3a6f7` | **2.16:1** | ✗ | ✗ |

**这是全 app 最重要的那颗按钮** ——「开收据」「储存」「确认」都是它。
按钮右半边 **2.16:1**，比灰底灰字还糟。而且按钮上的字通常不是大字，
所以连 3:1 的宽松门槛都救不了它。

对 70 岁的使用者，这不是「有点难读」，是**在最关键的那一步看不清楚要按什么**。

**改法**（同一个色系，只是压深，视觉几乎不变）：

```diff
- from-[#7c6cf5] to-[#b3a6f7]
+ from-[#5b4bd6] to-[#6f5ef2]
```

| 新色 | 白字对比度 |
|---|---|
| `#5b4bd6` | **6.14:1** ✓ |
| `#6f5ef2` | **4.61:1** ✓ |

四个地方要一起改（`button.tsx:13`、`glass.tsx:136`、`sidebar.tsx:50`、`sidebar.tsx:193`）。
**建议顺手把它变成一个 token**（`--v2-grad-primary`），
不然下次再加一颗按钮又会是 hardcode。

> `--v2-primary: #7c6cf5` 本身可以留着当**装饰色**（阴影、focus ring、图示底），
> 只是不能再当「白字的底」。

## 🔴 2. 五个 GlassBadge 有四个不合格 —— 而它是全产品最常出现的标签

`glass.tsx:90-97` 的 `toneMap`，底色 `tone-400/15` 叠在玻璃上、文字 `tone-600`：

| tone | 现在的文字色 | 对比度 | | 外框 ring 对玻璃 |
|---|---|---|---|---|
| `confirmed` 已确认 | `emerald-600` | **3.26:1** | ✗ | 1.22:1（需 3.0）✗ |
| `check` 请核对 | `amber-600` | **2.82:1** | ✗ | 1.16:1 ✗ |
| `missing` 笔记里没有 | `rose-600` | **3.89:1** | ✗ | 1.32:1 ✗ |
| `info` | `sky-600` | **3.51:1** | ✗ | 1.24:1 ✗ |
| `neutral` | `slate-600` | 6.44:1 | ✓ | 1.27:1 ✗ |

`ConfidenceBadge` 是 `CLAUDE.md` 规则 9 的核心视觉语言，
出现在**每一个会议记录栏位、每一笔捐款列、每一列 filings**。
它的工作是让人一眼看出「AI 这里有没有把握」——
如果它本身就看不清楚，整个「人类确认」的设计前提就被削弱了。

`check`（请核对）**2.82:1 是五个里最糟的**，而它正是最需要被看见的那一个。

**改法 —— 一行**：把 `-600` 全部换成 `-800`，底色 alpha 不用动。

```diff
- confirmed: "bg-emerald-400/15 text-emerald-600 ...
- check:     "bg-amber-400/15   text-amber-600   ...
- missing:   "bg-rose-400/15    text-rose-600    ...
- info:      "bg-sky-400/15     text-sky-600     ...
- neutral:   "bg-slate-400/15   text-slate-600   ...
+ confirmed: "bg-emerald-400/15 text-emerald-800 ...
+ check:     "bg-amber-400/15   text-amber-800   ...
+ missing:   "bg-rose-400/15    text-rose-800    ...
+ info:      "bg-sky-400/15     text-sky-800     ...
+ neutral:   "bg-slate-400/15   text-slate-800   ...
```

结果（全部一次到位，而且留了余裕）：

| tone | `-800` 色码 | 新对比度 |
|---|---|---|
| confirmed | `#065f46` | **6.65:1** ✓ |
| check | `#92400e` | **6.28:1** ✓ |
| missing | `#9f1239` | **6.63:1** ✓ |
| info | `#075985` | **6.48:1** ✓ |
| neutral | `#334155` | **8.80:1** ✓ |

> 为什么不用 `-700`：`check` 的 `amber-700` 只有 **4.45:1**，
> 差 0.05 就过 —— 那种边缘值不值得赌，直接用 `-800`。
> 深色模式那一半（`dark:text-*-300`）已经在 `globals.css` 的 palette flip 里处理过，不用动。

**同时建议加一个非颜色的讯号（WCAG 1.4.1）**：
三个 tone 现在有文字标签（好），但外框 1.2:1 等於看不见，
所以在**扫视**的时候（财政快速看一整页哪几列要处理），
资讯实际上只剩「颜色」在传达。而且老年人水晶体黄化，**最先失去的正是琥珀/黄与绿的分辨力** ——
偏偏就是 `check` 和 `confirmed` 这两个。

在 badge 前面加一个字形就解决：`✓` / `!` / `✕`（或 lucide 的 `Check` / `AlertTriangle` / `X`）。
`GlassBadge` 已经有 `gap-1.5`，塞得进去，不用改版面。

## 🟠 3. 边框与分隔线：非文字对比度不足

WCAG 1.4.11 要求「传达资讯的非文字元素」≥ **3:1**。

| 元素 | 现况 | 对比度 |
|---|---|---|
| `--v2-outline-border: rgba(80,74,130,0.32)` | outline 按钮的边 | **1.68:1** ✗ |
| `sidebar.tsx:45` `HAIRLINE = text-soft/15` | 侧栏分组线 | **1.26:1** ✗ |
| badge 的 `ring-*-400/30` | 见上表 | 1.16–1.32:1 ✗ |

**outline 按钮那条最要紧** —— 边框是「这是一颗可以按的东西」的唯一提示。
`0.32` → **`0.7`** 就到 **3.62:1**。

```diff
- --v2-outline-border: rgba(80, 74, 130, 0.32);
+ --v2-outline-border: rgba(80, 74, 130, 0.7);
```

侧栏的 hairline 就算拉到 `/55` 也只有 2.64:1 —— alpha 这条路走不通。
但**纯装饰性的分隔线不在 1.4.11 范围内**，所以务实的判准是：

- **表格的列分隔线**（`/money` 的捐款表、`/filings`）→ 它承载「哪一列是哪一列」，
  要用够深的实色（`--v2-outline-border` 那个 token 就够）
- **纯视觉的群组线**（侧栏分组）→ 可以留着

## 🟡 4. 一个 Capacitor 上会踩到的

`.v2-glass` 靠 `backdrop-filter: blur(24px)`。
旧版 Android WebView 不支援 `backdrop-filter` 时，**背景会整个不见** ——
不是变成不透明白，是变成**透明**，文字直接落在会动的粉彩渐层块上。

`--v2-text` 15:1 撑得住，但 badge 那几个（已经不合格）会更糟。
建议加一层 fallback：

```css
@supports not (backdrop-filter: blur(1px)) {
  .v2-glass, .v2-glass-strong { background: rgba(255, 255, 255, 0.96); }
}
```

`docs/MOBILE_APP_SETUP.md` 有提到 Capacitor 打包，所以这不是假设性问题。

## 5. 深色模式 —— 2026-08-07 补做（原本这一节不存在）

**方法**：把深色渐层的中间色站 `#171526` 当底，叠上 `.v2-glass`
得到实际合成色 **rgb(46, 44, 60)**，再算每一个前景。

### 先讲结论：**文字从来不是问题，边框才是。**

| 元素 | 对比度 | |
|---|---|---|
| `--v2-text` `#f1f5f9` | **12.38:1** | ✓ 超 AAA |
| `--v2-text-soft` `#c5c1dd` | **7.78:1** | ✓ 超 AAA |
| badge `emerald-300` | 6.62:1 | ✓ |
| badge `amber-300` | 6.74:1 | ✓ |
| badge `rose-300` | 5.71:1 | ✓ |
| badge `sky-300` | 6.16:1 | ✓ |
| badge `slate-300` | 7.05:1 | ✓ |

`globals.css` 的 palette flip 做得是对的 —— 深色模式的**字**全部合格。

### 真正坏掉的是每一条边（WCAG 1.4.11 要 3:1）

| 变数 | 原值 | 对比度 | 改成 | 新对比度 |
|---|---|---|---|---|
| `--v2-border` | `rgba(255,255,255,0.22)` | **2.03:1** ✗ | `0.45` | **4.03:1** ✓ |
| `--v2-outline-border` | `rgba(255,255,255,0.3)` | **2.61:1** ✗ | `0.55` | **5.25:1** ✓ |
| `--v2-glass` | `rgba(255,255,255,0.1)` | 几乎不构成一个面 | `0.14` | 面板与背景分得开 |

**这解释了 J 说的「看不清楚」和「有点透明，有点难读」是同一件事**：
每一个字都读得到，但卡片、面板、outline 按钮的**边界**看不见，
所以整个画面糊成一片深色，人分不出哪里到哪里是一块、哪个东西可以按。

> **教训**：对比度审查只算「文字 vs 底色」会漏掉一整类问题。
> 深色模式最先坏的通常不是文字（因为大家都会记得把字调亮），
> 是那些用 `rgba(255,255,255,0.2)` 随手写出来的边线。

### 深色模式还没验的

- 白字紫渐层在深色下**跟浅色一样**（渐层是硬编码的，不随主题变）—— 已经一起改掉了
- `/login` 深色未验（白字在使用者自选照片上，仍然取决于图片）
- `--v2-mint` `#67cea4` 配白色 = **1.92:1**。它只出现在 Minit logo chip 与 AI 浮动按钮的
  渐层末端（`via-… to-[#67cea4]`）。那是**品牌色**，改它是设计决定不是无障碍修补，
  所以留着没动 —— 但如果那颗浮动按钮的图示是唯一可点提示，严格说它需要 3:1。**待决。**
