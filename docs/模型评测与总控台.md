# 模型评测与总控台 — 用真实数据决定用哪一支，在画面上换

> **固定档名，改设计覆盖它。**
> 写于 2026-08-20 深夜 · J 决定：
> 「**我需要从新做过对比，不要一直只死拿着之前那个 95.2%，我可以花一些代价让每个模型真是对比，
> 不要把偏见保留下来，要有真实数据哪一个才是真正的性价比。**
> 用哪一个模型我希望总控那边可以自己调。然后那边我可以做测试，各种各样。然后还有语音的也是。」

---

## 0. 现在的实况（2026-08-20 实查，不是抄的）

| 查什么 | 结果 |
|---|---|
| `eval/` 有东西吗 | ✅ **有。** `run-eval.ts` ＋ **9 个 golden case**（含中文、乱帐、章程），跑的是**真的管线**（同样的 prompt、provider、zod） |
| eval 会量成本吗 | ❌ **不会。** 只量准确率 |
| eval 会量速度吗 | ❌ **不会。** 只有一个 `sleep()` 避开限速 |
| eval 一次跑几支模型 | ❌ **一支。** 跑 `resolveModel()` 回什么就是什么 |
| 模型设定在哪 | 🔴 **环境变数**（`AI_MODEL_EXTRACT` 等 4 支），在 `src/lib/ai/provider.ts:106`。**改一次要重新部署** |
| 语音 | ❌ **完全没有。** 全 `src/` 找不到任何 transcribe／audio／whisper 的实作 |

**所以「95.2%」是：一支模型 × 一批 case × 只量准确率 × 没量成本 × 没量速度。**
拿它当「性价比最高」的证据是不成立的 —— 它根本没有跟任何东西比过。
J 说得对。

---

## 1. 三件事，一条线

```
① 评测台（bake-off）  →  产生真实数据：准确率 × 成本 × 速度
        ↓
② 总控台改模型         →  照数据换，改一行资料，不用部署
        ↓
③ 测试台（playground） →  丢一张照片，并排看几支模型现在的表现
```

**顺序不能反。** 先有数据，才有得选；有得选，才需要一个换的地方。

## 2. 评测台 —— 让每支模型跑同一批东西

### 2.1 要改什么（`eval/run-eval.ts` 已经做对了八成）

| 加什么 | 怎么加 |
|---|---|
| **模型可指定** | `resolveModel()` 现在只读 env。加一个可选参数：`runEval({ model: "gemini:gemini-3.5-flash-lite" })` |
| **跑一串模型** | `npm run bench` 吃一份模型清单，**同一批 case 每支跑一遍** |
| **量成本** | 每次呼叫记 `promptTokens` / `completionTokens` → 套 `src/lib/ai/gemini.ts`／`openai.ts` 已经有的价格表 → `cost_micros`。**这套东西成本计量已经在用了，不用重写** |
| **量速度** | 呼叫前后 `performance.now()`，记 p50 / p90 |
| **量稳定度** | 🔴 **同一个 case 跑 3 次。** 一次跑准不算准 —— LLM 有随机性，量一次的「95.2%」可能下次是 88%。**这一条是让数字变成真数据的关键** |
| **出一张表** | 准确率 · 成本／份 · 秒／份 · 三次之间的落差 |

### 2.2 输出长这样

```
TASK: extract (读手写会议记录) · 9 cases × 3 runs
────────────────────────────────────────────────────────────────────────
模型                              准确率   落差    RM/份    秒/份   评语
gemini:gemini-3.5-flash-lite      95.2%   ±2.1   0.0089    3.4    现役
gemini:gemini-3.7-flash           97.8%   ±0.6   0.0223    4.1    +2.6% / 2.5 倍价
openai:gpt-5-nano                 91.4%   ±4.8   0.0051    2.9    便宜但不稳
openai:gpt-5.6-luna               98.1%   ±0.5   0.0410    6.2    最准，4.6 倍价
────────────────────────────────────────────────────────────────────────
```

**「落差」那一栏跟准确率一样重要。** ±4.8 的意思是「有时候 96%，有时候 87%」——
那种模型不能拿去读法定纪录，再便宜都不行。

### 2.3 四个任务分开量

`classify`／`extract`／`chat`／`long_doc` **各自量、各自选**。
现在的分流（extract 用 Gemini、chat 用 nano）是**猜的**，量完可能整个不一样。
🔴 **不要用一支模型的成绩去推论另一个任务。**

### 2.4 结果存进资料库，不是只印在萤幕上

```sql
create table model_bench_runs (
  id bigserial primary key,
  task text not null,              -- classify | extract | chat | long_doc | transcribe
  provider text not null,
  model text not null,
  cases int not null,
  repeats int not null,
  accuracy numeric,                -- 0..1
  accuracy_spread numeric,         -- ± 几个百分点
  cost_micros_avg bigint,
  latency_ms_p50 int,
  latency_ms_p90 int,
  notes text,
  ran_at timestamptz not null default now()
);
```

**这样总控台才看得到「我上次量的结果是什么」**，而不是每次都要重跑。
🔴 **`ran_at` 要显示在画面上** —— 三个月前量的数字跟今天的模型价格没有关系。

### 2.5 花多少钱

9 cases × 3 runs × 4 支模型 ＝ **108 次呼叫**，一个任务。
以现在的价格，`extract` 那一轮大概 **RM 2–5**。四个任务全量 **RM 10–20**。

J 说「我可以花一些代价」—— 就是这个量级。**这是这个专案最划算的一笔钱**，
因为它决定了之后每一次呼叫的单价。

## 3. 总控台改模型 —— 设定是资料，不是程式码

### 3.1 现在的问题

`resolveModel()` 读 `process.env`。改模型 = 改 Vercel 环境变数 = **重新部署**。
而且**改错了没有任何东西会挡** —— `check-ai-routing.ts` 的档头自己写着
「`AI_MODEL_CHAT=gpt-5-nano`（少了冒号）会安静失败」。

### 3.2 改成资料表（跟 `plan_entitlements` 同一个思路）

```sql
create table ai_model_config (
  task text primary key
    check (task in ('classify','extract','chat','long_doc','transcribe','embed')),
  provider text not null check (provider in ('gemini','openai')),
  model text not null,
  updated_at timestamptz not null default now(),
  updated_by uuid,
  note text                        -- 「2026-08-22 bench：+2.6% 值得」
);
```

**`resolveModel()` 的顺序变成**：

```
资料表 ai_model_config  →  环境变数 AI_MODEL_*  →  内建预设
```

⚠️ **环境变数不要删**，留成 fallback。理由跟 `monthly_free_quota` 一样：
新的坏掉时旧的还在，而且本机开发不必连资料库。

### 3.3 画面（`/admin` 里一页）

| 任务 | 现在用 | 上次量的成绩 | 换成 |
|---|---|---|---|
| 读手写（extract） | `gemini-3.5-flash-lite` | 95.2% ±2.1 · RM0.0089 · 3.4s（8/22 量） | ▼ 下拉 |
| 分类（classify） | `gpt-5-nano` | 99.1% ±0.3 · RM0.0002 · 0.8s | ▼ |
| 对话（chat） | `gpt-5-nano` | — **没量过** | ▼ |
| 长文件（long_doc） | `gemini-3.5-flash-lite` | — 没量过 | ▼ |
| 语音（transcribe） | — 还没做 | — | ▼ |

**下拉选单的选项从哪来**：一支 `/api/admin/models` 去问 Gemini 与 OpenAI
「你现在有哪些模型」（`check-ai-routing.ts` 已经会做这件事）。
🔴 **不要写死清单** —— 写死的清单三个月后就是错的，这正是 `text-embedding-004` 那次踩到的。

### 3.4 三条护栏

1. **存之前先打一次。** 选了新模型 → 送出前先用它跑一个最小请求 → 打不通就不给存。
   （这直接解决「少一个冒号安静失败」那个坑。）
2. **每次改写一行审计**（`platform_actions`：谁、什么时候、从哪支换到哪支、为什么）。
3. 🔴 **改模型会让 `unit-economics.ts` 的数字过期。** 存档之后画面上要提醒
   「跑 `npm run economics` 重算」，而且 deck／one-pager 里的数字要跟着换。

## 5. 语音 —— 现在完全没有

### 5.1 是什么

社团开会**没有人会一边开一边打字**。现在的流程是「开完会 → 有人手写 → 拍照 → Minit 读」。
语音是把它变成「**开会时录音 → Minit 直接读**」，少掉手写那一步。

⚠️ **但手写那条路不能拿掉。** 很多社团还是会写在本子上，那是他们的习惯，
而且录音在吵杂的会所里未必比手写清楚。**语音是多一条路，不是取代。**

### 5.2 形状

```
录音（.m4a / .mp3）
   ↓  transcribe（新任务，新模型格）
逐字稿（text）
   ↓  走现有的 extract-meeting-notes 那一条（一个字都不用改）
结构化的会议记录
   ↓
人看过、改过、按确认
```

🟢 **好消息：第二段完全不用重做。** 逐字稿就是文字，
而 `extract-meeting-notes` 本来就吃文字（`read-roster.ts` 已经在做同样的事）。
**所以语音真正要写的只有「录音 → 文字」那一段。**

### 5.3 要定的

| 要定什么 | 候选 | 备注 |
|---|---|---|
| 模型 | Gemini 吃 audio input · OpenAI `whisper` / `gpt-4o-transcribe` | 🔴 **要进第 2 节的 bake-off** —— 马来西亚社团讲的是**华语＋马来文＋方言混着**，这一格谁强完全是要量的，不能猜 |
| 环境变数／设定 | `AI_MODEL_TRANSCRIBE`（＋ `ai_model_config` 的 `transcribe` 那一列） | |
| 录音存不存 | 🔴 **建议：逐字稿留，录音档跟原始照片同一条规矩**（`photos.kept_months`，会真的删，删之前七天提醒） | 录音是 PDPA 上最敏感的东西之一 —— 里面有每个人的声音 |
| 长度上限 | 一小时的会 ≈ 很大的档 | 要有上限，而且要在**上传前**就挡，不是传完才说不行 |
| 计价 | 语音按**分钟**算，不是按份 | 直接对上第 6 节的百分比额度 |

### 5.4 一定要有的一句话

> **录音之前，画面上要出现：「录音前请先告诉在场的人。」**

不是法务洁癖 —— 马来西亚 PDPA 下，录下别人的声音要有告知。
而且社团里录音这件事本身是敏感的，**先讲，比事后解释便宜**。

## 6. 🔴 额度改成百分比 —— J 推翻了「讲份数」

**J 2026-08-20：「我觉得还是不能使用次数，太危险了。还是用 PERCENTAGE。
你说人看不懂 TOKEN，就换成 PERCENTAGE，像现在各厂家用的。」**

### 6.1 我之前写错了

`方案与权益设计.md` 第 3 节写着「🔴 讲份数，不要讲 credits／tokens／额度」，
理由是「对长辈『还可以拍 8 份文件』比『剩 8%』具体」。

**那个理由只顾了看得懂，没顾成本。J 抓到的正是这一点：**

| 一「份」 | 真实成本 |
|---|---|
| 拍一张便条纸 | 约 RM0.002 |
| 读一本 30 页章程（`long_doc`） | **几十倍** |
| 一小时录音（之后有语音的话） | **更多** |

**「次数」根本不是成本的代理。**
免费层给 100 次，只要有人全部拿去读 30 页章程，成本就爆掉 —— 而**帐面上他还在额度内**。
这不是理论，`extract-constitution` 自己的注解就写着它是全 app 最贵的一格。

### 6.2 改成什么

**额度的单位从「次」改成「用量」，画面上显示百分比。**

```sql
-- 取代 ai.monthly_actions
plan_entitlements: key = 'ai.monthly_budget_micros'   -- 每月成本预算
```

| | |
|---|---|
| **内部记什么** | 每次呼叫的真实 `cost_micros`（**已经在收了**，`20260803000000_ai_usage_cost.sql`）|
| **画面显示** | `已用 / 预算` → **一个百分比 ＋ 一条 bar** |
| **撞墙** | 「这个月的 AI 用量用完了。**下个月 1 号会重来。**」 |

🟢 **这样反而对一般使用者更宽松**：拍便条纸扣得极少，一个月可以拍很多张；
真正被挡住的是那个「一直丢 30 页章程进来」的用法 —— **而那本来就是该挡的那一个**。

### 6.3 一个实作上的真问题

**成本要打完才知道**，所以不能精准预扣。做法：

1. 打之前只检查「**还有没有余额**」（`> 0` 就放行）
2. 打完把真实 `cost_micros` 记进去
3. 最后一次**可能超一点点** —— 可接受，各厂家也是这样
4. 🔴 **但要有「单次上限」**：一次呼叫不能吃掉整个月。
   超过就先挡下来，讲清楚「这份文件太大，__ 方案一次读 __ 页」
   —— `doc.max_pages` 在这里仍然有用，它变成**防单次爆炸的保险**，不再是主要的墙

### 6.4 画面上显示什么、不显示什么

| 显示 | 不显示 |
|---|---|
| ✅ 「本月 AI 用量 ▓▓▓▓▓░░░░░ **58%**」 | ❌ RM 金额 |
| ✅ 「用完了，下个月 1 号重来」 | ❌ token 数 |
| ✅ 「这份文件太大，一次读不完」 | ❌ 次数 |
| ✅ 加购、换方案的出路 | ❌ 我们的成本 |

**`方案与权益设计.md` 第 3 节那张表要照这个重写。**

## 7. 🔴 使用者不能问 AI 自己用了多少 —— 我也写错了

**J 2026-08-20：「然后用户没办法问 AI 这个月用了多少 AI，还是多少 TOKEN 什么的。」**

`助手重做-设计.md` 把 `guna_ai(period)` 列成**第一支工具**，还写着「20 分钟就能写」。
**那一支要拿掉。**

### 为什么这不是「又砌墙」

这跟「AI 看不到你的会议记录」**不是同一件事**，差别要讲清楚，
否则下一个 session 会以为规则又转回去了：

| | 该不该给 AI 看 |
|---|---|
| **他们自己的会议记录、捐款、章程、名单** | ✅ **该。** 那是**他们的资料**，看不到就没用，就是 J 推翻的那一条 |
| **我们的 token 数、RM 成本、单价** | ❌ **不该。** 那是**我们的营运资料**，不是他们的 |

三个理由：

1. **那是我们的成本结构。** 把「一次呼叫 RM0.0089」讲给使用者听，等于把毛利公开。
2. **会被拿来钻。** 知道哪种输入贵，就知道怎么榨免费层。
3. **它跟画面矛盾。** 画面刻意只讲百分比（第 6.4 节），助手却报得出金额，那道墙等于没有。

### 使用者问了要怎么回

> 「您这个月的 AI 用量在 **设定 → AI 用量** 那一页，现在用了 58%。
> 详细的费用我这边看不到。」

＋ 一颗「去那一页」的按钮（`pergi` 工具本来就有）。

**百分比可以讲**（画面上本来就写着），**金额和 token 不可以**。

### `助手重做-设计.md` 要跟着改

- 工具清单里 **删掉 `guna_ai`**
- 第 5 节的顺序第 1 项本来是 `guna_ai`，**换成 `cari_minit`**
  —— 那本来就是 J 更想要的那一件（「我记得有一次开会说了什么」）
- J 自己要看用量与成本，在 **`/admin`**（`方案与权益设计.md` 第 5.1 节已经写好了）

## 9. 不要做的

| 不要 | 为什么 |
|---|---|
| 拿 95.2% 当「性价比最好」的证据 | 它没跟任何东西比过，也没量成本和速度 |
| 用一支模型的成绩推论另一个任务 | 四个任务各自量 |
| 只跑一次就下结论 | LLM 有随机性。**跑 3 次，看落差** |
| 把模型清单写死在程式码里 | 三个月后就是错的（`text-embedding-004` 那次） |
| 让使用者看得到 RM 或 token | 第 7 节 |
| 用「次数」当额度单位 | 第 6 节 |
