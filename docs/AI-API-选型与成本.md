**所以真正会烧掉你钱的不是「选哪个模型」，是「没有护栏」：**

1. **没有速率限制** —— 有人 3 秒打 100 次，或者拿你当免费 AI proxy

**这四件加起来，比模型选错贵一个数量级。** 先做护栏，再挑模型。

### 1.1 「Gemini 3.6 出了」—— 出了，但那不是你要的

3.6 Flash 是 2026-07-21 发布的，**$1.50/$7.50**，比你现在用的 3.5 Flash 只便宜一点点输出，
**贵 gpt-5.6-luna 7.5 倍**。

你要的不是「最新」，是**「够准 + 最便宜」**。
读一页手写捐款簿并吐出结构化 JSON，是一个**窄任务**，
不需要前沿推理能力 —— 需要的是够好的 OCR 加听话的 JSON 输出。
在这种任务上，Lite / nano / luna 这一档常常跟旗舰打平，而价格差 5–25 倍。

**这句话有没有成立，你的 eval 会告诉你。这正是它存在的意义。**

### 1.2 GPT-5.6 luna 是这一轮最有意思的一个

- **$0.20/$1.20**，比 Gemini 最便宜的 Flash-Lite 还便宜
- **确认支援图片输入**（OpenAI 官方与多个 vision 评测都列了它）
- **1.5M context** —— 一份 60 页章程一次塞得下，不用分段（省掉你 D3 第 4 点的工程）
- **cached input $0.02 = 输入价的 1/10**
- **Flex 层 $0.10/$0.60** —— 同步呼叫、只是排程较慢，直接 5 折

⚠ 但它是**新模型**，而你的任务（马来文 + 中文手写混语）不是它评测里会测的东西。
**不要因为便宜就换过去 —— 要用 eval 换。**

### 1.3 为什么我不建议 DeepSeek 和 Kimi（虽然 DeepSeek 最便宜）

三个理由，第二个是决定性的：

1. **PDPA 跨境。** 资料送到中国。你处理的是**敏感个资**（庙宇捐款名册揭露宗教信仰，
   见 `legal/PDPA-合规说明.md` 第 2.1 节）。2025 年的跨境传输指引下，这比送到
   Google / OpenAI 难辩护得多 —— 而且这是**庙的委员会一定会问的问题**。

2. **DeepSeek 已经宣布尖峰时段全项目 2 倍收费，时段是北京时间 09:00–12:00 与
   14:00–18:00 —— 那跟马来西亚是同一个时区。**
   也就是说：**你的使用者上班时间，就是你的成本翻倍时间**，
   而**生效日期尚未公布**。把成本模型建立在这上面，等于把 deck 那一页的数字交给别人决定。

3. **Kimi K2.6 $0.95/$4.00 比 Gemini Flash-Lite 贵三倍**，没有价格优势可言。

**但有一件事值得记下来**：DeepSeek 和 Kimi 是**开源权重**。
所以「以后可以自架，资料完全不出马来西亚」是一个真实的路线图选项 ——
而且在竞赛上，「资料主权」是很好的一句话。
只是那是 Phase 9，不是现在。你现在连付费 API 都还没开。

## 1.6 「优惠会到多久」—— 这个问题的答案跟你想的不一样

我查了所有能查到的日期。**真正会到期的只有一个：**

| 项目 | 类型 | 到期日 |
|---|---|---|
| **Claude Sonnet 5 $2/$10** | **限时促销** | **2026-08-31** → 9/1 起 $3/$15（**涨 50%**）· 官方明文标注 |
| Gemini 2.5 Flash-Lite 退役 | 停售 | 2026-10-16 ⚠ 第三方报导，请自行确认 |
| DeepSeek 尖峰 2 倍收费 | **待实施的涨价** | **未公布生效日** —— 这才是最该警惕的 |
| Gemini 免费层 | 一直有 | 无到期日，但「输入会被拿去训练」 |
| OpenAI Flex（5 折） | **服务层，不是促销** | 无到期日 |
| Batch API（5 折，三家都有） | **服务层** | 无到期日 |
| Prompt caching（1 折） | **服务层** | 无到期日 |

**关键分辨：这个市场的「便宜」有三种，只有一种会到期。**

1. **限时促销**（Sonnet 5）—— 会到期。**不要把成本模型建在这上面。**
2. **服务层折扣**（Batch / Flex）—— 永久，代价是**延迟**。5 折，你用等待换。
3. **快取折扣** —— 永久，**代价是零**（如果你的 prompt 是重复的）。

**Minit 的 prompt 每次都一模一样，只有照片在变。** 所以第 3 项是白捡的 ——
财政一次上传 15 页捐款簿的时候，第 2 页开始的 prompt 都是快取命中。
（低用量时快取会过期，所以这不是每次都有；但**连续上传那一批一定有**。）

**而更根本的一点**：与其追优惠，不如让**换模型变成一件五分钟的事**。
你已经做对了一半 —— `AI_PROVIDER` 和 `GEMINI_MODEL` 都是环境变数。
再加上 1.5 节那个按任务分流，你就永远不需要因为谁涨价而恐慌：
改一个环境变数，跑一次 eval，看数字。

**唯一一个我建议你抓住的日期是 8/31** ——
不是为了用 Sonnet 5 上线，而是**如果你想拿它当 eval 的「准确率天花板」参考点，
就要在 8/31 之前跑完**，不然基准价变了，deck 里的比较表会对不上。

## 4. 语音要不要做 —— 价格不是问题，准确率才是

价格已经证明不构成障碍（一场 AGM RM0.29–3）。真正的三个问题：

**(1) 马来语 / 华语 / 方言 / 英语混讲，加上老人口音和庙里的回音 ——
这是 ASR 最难的情境，比手写还难。**
手写至少是静态的、可以放大重看；录音里一句听错就是错了。
而且多数模型的马来语训练资料远少于英语，**方言（福建话、广东话）基本上没有**。

**(2) 一句听错的会议决议，就是一份错的法定文件。**
所以就算做，也必须套同一条法则：**AI 出草稿，人确认**，
而且要能**点一句话跳回录音的那一秒**去核对。这个 UI 比转录本身难做。

**(3) PDPA：录一场会员大会，在场每一个人都是当事人。**
要不要事先告知与同意？（我倾向要。）这又回到 `legal/` 那两份文件。

**我的建议：先不要做转录，但先做一件更小、更值钱的事** ——

> **让使用者用「讲的」代替「打字」修正栏位。**
>
> 现在审核画面上，AI 标了「请核对」的栏位要用键盘改。
> 对一个 70 岁、用马来文打字很慢的财政，那正是 `CLAUDE.md`「eROSES 法则」
> 想消灭的那种摩擦 —— **只是它躲在修正流程里，没被发现。**
>
> 讲一句「不是三百，是三百五十」→ 转成文字 → 填进那一格。
> 每次只有几秒钟的音讯，成本趋近于零，**而且错了当场看得到、当场再讲一次**。
